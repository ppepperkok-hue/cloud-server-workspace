# ADR-0002：探测宝塔面板必须带浏览器 User-Agent

- **状态**：已接受
- **日期**：2026-09-28
- **决策者**：agent

## 背景

给 bt-he1k 开启面板 SSL 与 IP 白名单后，用 `curl`（不带 User-Agent）探测 `https://<TEST_HOST_IP>:8888/<PANEL_ENTRY>` **一律返回 404**（146 字节、`Server: nginx` 的标准 404 页）。同一时刻、同一状态下，带浏览器 UA 的请求返回 **200**，正文 30599 字节，标题 `宝塔面板·腾讯云专享版`。

这个 404 与 SSL、IP 白名单、面板重启都无关。我做了隔离实验逐一排除：

| 状态 | 无 UA | 浏览器 UA |
| --- | --- | --- |
| SSL 开 + 白名单有值 | 404 | 200 |
| 白名单清空 + SSL 开 | 404 | 200 |
| 白名单清空 + SSL 关 | 404 | 200 |
| 恢复 SSL | 404 | 200 |

结论：宝塔面板 11.8 对非浏览器 UA 做了**反扫描拦截**，直接返回 404，且响应体不带任何提示——极容易被误判成「面板被改坏了」，进而错误触发回滚。

## 决策

凡是自动化探测宝塔面板（curl、健康检查脚本、变更后的验证步骤），**一律显式带浏览器 User-Agent**；并把「无 UA 得到 404」当作**预期行为**而非故障。

## 备选方案与权衡

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 直接 `curl` 看状态码判定面板健康 | 最简单 | 404 假阳性，会诱导错误的止损/回滚 | ❌ |
| 带浏览器 UA + 校验响应体标题 | 结果可信，能区分「UA 拦截」与「真故障」 | 多一个 `-A` 参数 | ✅ |
| 靠 403/200 区分 IP 白名单是否生效 | 白名单命中返回 403，与 UA 的 404 明显不同 | 需要一个非白名单来源才能验证 | ✅ 辅助 |

## 后果

- 健康检查与验证脚本必须带 `-A "<browser UA>"`，并在注释里写明原因（脚本内已注明）。
- 404 的判定规则细化，写进 runbook：**无 UA 的 404 = 正常**；带 UA 仍 404 且正文不是登录页 = 真故障。
- IP 白名单被触发时返回 **403**（已在 `harden-bt-panel.sh` 的双向验证中实测：白名单设为 `8.8.8.8` 时本机得 403，改回本机出口 IP 得 200）。
- 这条同样适用于其它「会伪装 Server 头、对非浏览器 UA 静默 404」的国产面板，遇到时先换 UA 再排查。
