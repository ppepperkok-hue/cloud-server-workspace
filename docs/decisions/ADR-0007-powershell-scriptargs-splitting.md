# ADR-0007：`-ScriptArgs` 用空格分隔多个参数，逗号不是分隔符

- **状态**：已接受
- **日期**：2026-10-21
- **决策者**：agent

## 背景

`ssh-bt-he1k.ps1` 有一个 `-ScriptArgs` 参数，用来把参数传给远端脚本的位置参数（`$1`、`$2`…）。`harden-bt-panel.sh` 需要两个参数：白名单 IP 与面板对外地址。

runbook 里原本写的是：

```powershell
-ScriptArgs <OPERATOR_IP>,<TEST_HOST_IP>
```

这条命令**根本跑不通**，而且失败方式很隐蔽：`powershell -File` 下，PowerShell 5.1 把整个 `-ScriptArgs` 值绑成**一个**字符串（实测 `count=1`，`arg[0]=[203.0.113.50,203.0.113.10]`），于是远端脚本把整串当成白名单，`$2` 为空，脚本以 `no host address given` 退出 2。看上去像「脚本参数校验太严」，实际是**调用方式没把参数送到**。

逐个实测（PowerShell 5.1.26100.9710，本机无 pwsh）：

| 形式 | 结果 |
| --- | --- |
| `-File ... -ScriptArgs 'a,b'` | 1 个元素 `a,b`（逗号不拆） |
| `-File ... -ScriptArgs 'a' 'b'` | **报错**「A positional parameter cannot be found that accepts argument 'b'」 |
| `-File ... -ScriptArgs 'a b'` | 1 个元素 `a b`（含空格） |
| `ValueFromRemainingArguments` | 同样报错，帮不上忙 |
| 交互式 `& .\x.ps1 -ScriptArgs 'a','b'` | 2 个元素（正确）——但 runbook 给的是 `powershell -File` 形式 |

也就是说：**在 `powershell -File` 下，PowerShell 5.1 没有办法把两个值绑成两个数组元素**。这个限制没法靠改参数声明绕过去，只能在包装脚本里自己拆。

另一个约束：包装脚本把参数拼进远端命令字符串（`... | bash -s $($ScriptArgs -join ' ')`）。PowerShell 5.1 传原生程序参数时，**一个多词字符串会作为单个 argv 元素送出去**——所以远端 bash 看到的是一整个 `203.0.113.50 203.0.113.10`，而不是两个参数。

## 决策

**在包装脚本里按空白拆分 `-ScriptArgs`，并把每个参数单独单引号后再拼进远端命令。**

- 多个参数之间用**空格**分隔：`-ScriptArgs "203.0.113.50 203.0.113.10"`。
- **逗号不是分隔符**：白名单本身就是逗号分隔的列表（`203.0.113.50,198.51.100.7`），按逗号拆会把一份白名单拆成两个参数。按空白拆则逗号原样留在参数里。
- 每个参数单引号包裹后拼进远端命令，单词内的空格不会在远端再被切开。
- 参数里含引号字符（`'` 或 `"`）直接**拒绝并报错**，不做静默转义——单引号无法安全地在单引号串里表示，与其猜，不如明说。

## 备选方案与权衡

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 保持逗号，runbook 照旧 | 不用改 | 逗号绑成单串，第二个参数根本到不了 | ❌ 实测否掉 |
| 改用 JSON 传参 | 无歧义 | 要改远端脚本的参数解析方式，超出这次范围 | ❌ 以后再说 |
| 改参数声明试图让 PowerShell 拆分 | 看起来最干净 | PS 5.1 的 `-File` 绑定行为不认这个 | ❌ 实测否掉 |
| **包装脚本按空白拆分 + 单引号包裹** | 改动小；逗号语义不受影响；单参数场景不变 | 一个参数内部不能带空格 | ✅ 采用 |

## 后果

- runbook 的调用形式改为 `-ScriptArgs "<OPERATOR_IP> <TEST_HOST_IP>"`，并写明「用空格、别用逗号」及原因。
- `ops-agent.md` 里的单参数用法（`-ScriptArgs $tok`）不受影响：单值按空白拆分后仍是一个参数。
- `rsh.ps1` 走 JSON 数组，本来就不受这个绑定问题影响。
- 包装脚本的 `-ScriptArgs` 帮助文本要写清这个约定，否则下一个人还会照旧写逗号。
- 远端 bash 收到的参数个数可以在本地用「假 ssh」验证：把一个只打印 argv 的替身放在 PATH 前面，再把包装脚本造出的远端命令**在本地 bash 里跑一遍**看 `argc`。整个验证不连任何服务器。
