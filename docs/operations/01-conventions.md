# 01 · 目录、命名与状态约定

本文件定义全工作区统一的技术约定，任何 agent 都按这一套执行，不临场发挥。

## 1. 目录职责（谁住哪，不许串门）

| 目录 | 只放 | 不放 |
| --- | --- | --- |
| `docs/` | 文档、规范、清单、决策、复盘 | 可执行代码 |
| `scripts/` | 可执行运维脚本（英文） | 配置、密钥、文档 |
| `infrastructure/` | Terraform/Ansible 等 IaC | 临时脚本 |
| `configs/` | 脱敏配置模板 | 含密钥的真实配置 |
| `secrets/` | 密钥（gitignore） | 任何会被提交/引用的内容 |
| `state/` | 运行状态、日志、看板 | 规范文档 |
| `templates/` | 文档模板 | 已填写的实例 |
| `logs/` `tmp/` | 运行日志 / 临时文件 | 需要长期保留的内容 |

## 2. 命名约定

- **文件名**：英文小写连字符（kebab-case），如 `deploy-app.sh`、`backup-db.sh`。
- **目录名**：英文小写单词，如 `healthcheck`、`postmortems`。
- **文档正文**：中文；**代码/脚本/注释/变量名**：英文。
- **时间戳**：`YYYY-MM-DD HH:MM:SS` 或 ISO 8601；文件名中的日期用 `YYYY-MM-DD`。
- **环境**：`prod` / `staging` / `dev`，不得自造 `生产`、`正式` 等别名。

## 3. 脚本约定

- 脚本开头写清用途、用法、前置条件、风险，用英文注释。
- 幂等：重复执行结果一致，不产生脏数据。
- 破坏性脚本：内部先做确认或支持 `--dry-run`。
- 所有脚本可被 `scripts/README.md` 索引到，新脚本必须更新索引。

## 4. 状态约定（`state/` 的三个文件）

| 文件 | 规则 |
| --- | --- |
| `CHANGELOG.md` | **追加式**，只增不改历史；格式见 `templates/operation-record.md` |
| `TASKS.md` | 每条任务标状态：`待办` / `进行中(owner)` / `已完成` / `阻塞(原因)`；认领先改状态 |
| `KNOWN-ISSUES.md` | 已知问题 + 影响 + 缓解措施；解决后标注日期，不删除 |

## 5. 变更记录

- 修改任何规范、目录结构、约定，必须在 `state/CHANGELOG.md` 记录原因。
- 不得悄悄改规范；改了文档不写日志 = 违规。
