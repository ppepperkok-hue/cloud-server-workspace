# 05 · 监控与告警基线

监控不是「装个工具」，而是**在用户发现问题前先知道**。新服务上线必须接入监控，这是默认动作。

## 1. 监控四层

| 层 | 监控什么 | 示例 |
| --- | --- | --- |
| 基础设施 | CPU、内存、磁盘、网络、负载 | 主机资源使用率 |
| 服务 | 进程存活、端口、健康检查 | 服务 HTTP 探活 |
| 应用 | 错误率、延迟、QPS、日志 | 应用指标 |
| 业务 | 关键业务指标 | 订单量、登录成功率 |

## 2. 告警规范

- 告警要**可行动**：收到告警知道该做什么，否则别告。
- 分级：`P0` 立即处理 / `P1` 30 分钟内 / `P2` 工作时间处理。
- 告警路由：明确谁接收、怎么通知（渠道）。
- 抑制与去重：避免告警风暴，同类告警聚合。

## 3. 必备告警清单（基线）

| 指标 | 阈值（示例） | 级别 |
| --- | --- | --- |
| 磁盘使用率 | > 85% | P1 |
| CPU 持续 | > 90% 持续 5 分钟 | P2 |
| 服务健康检查失败 | 连续 3 次 | P0 |
| 证书剩余天数 | < 14 天 | P2 |
| 备份失败 | 任意失败 | P0 |
| 错误率突增 | 5xx > 5% 持续 5 分钟 | P1 |

## 4. 服务上线接入清单

- [ ] 探活端点已就绪
- [ ] 关键指标已采集
- [ ] 告警规则已配置并测试过（故意触发一次确认能收到）
- [ ] 告警接收人已指定
- [ ] 监控配置写入 `infrastructure/` 或 `configs/`，并在 CHANGELOG 记录

## 5. 维护

- 告警规则变更走 CHANGELOG。
- 定期清理无效/噪音告警，保持信噪比。
- 监控本身也要被监控（监控挂了要知道）。
